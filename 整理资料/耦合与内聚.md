# 耦合与内聚

## 核心定义

**耦合（Coupling）** 和 **内聚（Cohesion）** 是 Larry Constantine 在 1960 年代末提出的两个互补概念，最初发表在他与 Wayne Stevens、Glenford Myers 合著的经典论文 *"Structured Design"*（IBM Systems Journal, 1974）中。

| | 耦合 | 内聚 |
|---|------|------|
| **问的问题** | 模块之间有多依赖？ | 模块内部有多聚焦？ |
| **好状态** | 低耦合（独立可替换） | 高内聚（单一职责，内部紧密） |
| **坏状态** | 高耦合（改一处牵全身） | 低内聚（模块内各元素互不相干） |
| **类比** | 人与人之间的依赖关系 | 一个人内心的专注程度 |

**关键洞察：低耦合让系统可维护，高内聚让系统有价值。** 两者必须同时追求——

- 低耦合 + 低内聚 = 一堆碎片（独立但没意义）
- 高内聚 + 高耦合 = 一团铁板（有意义但改不动）
- 低耦合 + 高内聚 = 好系统（独立且有意义）

---

## 耦合的类型（从好到坏）

| 类型 | 程度 | 说明 | 游戏设计类比 |
|------|------|------|-------------|
| **数据耦合** | 最好 | 模块间只传递数据，不传递控制信息 | 正交维度之间只通过数值交互 |
| **印记/标签耦合** | 较好 | 传递了数据结构但只用部分字段 | 传了整个角色对象但只读了攻击力 |
| **控制耦合** | 中等 | 一个模块控制另一个的流程 | 被动技能修改主动技能的行为 |
| **外部耦合** | 较差 | 依赖外部格式/协议/设备 | 依赖特定平台 API |
| **公共/全局耦合** | 差 | 共享全局数据结构 | 多个系统读写同一张全局表 |
| **内容耦合** | 最差 | 直接修改另一模块的内部数据 | 一个系统直接改另一个系统的私有变量 |

---

## 内聚的类型（从好到坏）

| 类型 | 程度 | 说明 | 游戏设计类比 |
|------|------|------|-------------|
| **功能内聚** | 最好 | 所有元素服务于同一个功能 | 一个技能只做一件事且做好 |
| **顺序内聚** | 好 | 输出→输入链式流动 | [[递进式设计]]：基础→进阶→质变 |
| **通信内聚** | 较好 | 操作同一份数据 | 所有战斗系统都作用于角色属性 |
| **过程内聚** | 中等 | 按执行顺序分组 | 按流程阶段分组（初始化→循环→结算） |
| **时间内聚** | 较差 | 只因"同一时间发生"而分组 | 开场初始化把所有系统一起启动 |
| **逻辑内聚** | 差 | 逻辑上相关但功能不同 | "所有随机事件"放在一起 |
| **巧合内聚** | 最差 | 纯粹偶然放在一起 | 代码里"工具函数大全" |

## 与游戏设计原则体系的映射

[[游戏设计原则体系]] 中的核心概念可以用耦合/内聚语言重新表述：

| 游戏设计概念 | 耦合/内聚表述 | 说明 |
|-------------|-------------|------|
| [[正交]] | 低耦合 | 规则维度互相独立，可逐维分解 |
| [[递进式设计]] | 高内聚（顺序内聚） | 每一层是下一层的前提，输出→输入链式流动 |
| [[以结构释放认知余量]] | 低耦合的体验效果 | 正交→认知减负→释放脑力 |
| [[以涌现性为目标]] | 低耦合 + 高内聚的涌现 | 维度独立（不退化）+ 每个维度有足够深度（可组合） |
| [[优雅的设计]] | 低耦合 + 高内聚的审美效果 | 少元素多内容 = 每个元素高内聚，元素间低耦合 |

### 规律备忘

> **正交性 + 递进式 = 涌现性的前提条件**
>
> 用耦合/内聚语言：
>
> **低耦合 + 高内聚 = 涌现性的前提条件**

低耦合（正交）保证维度之间不会互相干扰退化，高内聚（递进）保证每个维度内部有足够深的结构来产生"意外"。只有低耦合没有高内聚，维度虽然独立但每个维度都很浅——组合不出任何有意义的东西。这就是 [[Roguelike游戏的选择方式]] 里说"横向太宽玩家选不出来"的深层原因：宽度够了（低耦合），但每个选项的深度不够（低内聚），所以组合出来的东西没有惊喜。

## 与 vault 中已有笔记的连接

- [[正交]] — 低耦合在游戏设计中的表述。但 vault 中只有"低耦合"的智慧，缺少"高内聚"的对偶
- [[From MDA to DDE]] — MDA 的"Mechanics"类别是典型的低内聚（叙事、代码、界面全混在一起），DDE 把它拆成 Blueprint/Mechanics/Interface 三个高内聚子类
- [[System Design General Guidelines]] — 好系统五标准中，comprehensible/consistent/predictable/extensible 是低耦合的结果，elegant 是高内聚的结果
- [[不均匀比均匀好]] — 不均匀本质上是"高内聚"的体验表现：每个时刻有独特的聚焦，而非均匀地分散注意力
- [[关于平行内容生成]] — 追问"涌现性内容从哪来"，答案之一是：低耦合的维度各自高内聚地深入，然后组合出意外
- [[结构是认知引擎]] — 正交（低耦合）是认知减负的手段，但"减负后的脑力往哪去"需要高内聚的结构来承接

## 推荐资料

### 必读

1. **Stevens, W.P., Myers, G.J. & Constantine, L.L., "Structured Design", IBM Systems Journal, Vol. 13, No. 2, 1974, pp. 115-139**
   - 原始论文。耦合和内聚这两个概念的起源。Constantine 当时研究的是为什么某些大型软件系统比其他系统更容易维护，发现"模块间的关系模式"比"模块内部有多聪明"更能预测系统质量。

2. **GeeksForGeeks, "Software Engineering | Coupling and Cohesion"**
   - 最完整的入门综述，类型分类齐全，附有图示。
   - https://www.geeksforgeeks.org/software-engineering-coupling-and-cohesion/

### 进阶

3. **Robert C. Martin, *Clean Architecture*, 2017, Chapter 7-8**
   - Uncle Bob 把耦合/内聚重新包装为 SRP（单一职责原则）和 DIP（依赖倒置原则）。SRP ≈ 高内聚的等价表述，DIP ≈ 低耦合的等价表述。他的贡献是把这两个概念从"评估标准"提升为"设计行动指南"。

4. **Meilir Page-Jones, *The Practical Guide to Structured Systems Design*, 2nd Ed., 1988**
   - 对 Constantine 原始分类的扩展和实践指南，被认为是结构化设计领域最好的教科书。把耦合/内聚的度量从定性推向了半定量。

5. **Christopher Alexander, *Notes on the Synthesis of Form*, 1964**
   - 不是直接讲耦合/内聚，但 Alexander 的"适应性"概念（好的设计 = 在约束交集中找到适应）是两者的哲学前提。[[正交]] 笔记已在独立重新发现 Alexander 的路径。
