# Insight Dig

从知识库的结构缺陷中挖掘你尚未注意到的洞察。核心假设：**一个笔记的"未被充分思考"不是靠阅读记录判断的，而是靠结构痕迹推断的——矛盾、缺口、孤立、重复。**

## Scope

**This skill works on:**

| 场景 | 说明 |
|------|------|
| 日常知识库巡检 | 用户每天运行一次，检查整体知识库 |
| 定向领域审查 | 用户指定某个文件夹或主题，深入挖掘 |
| "换一个" | 用户对某个洞察不感兴趣，要求替换 |

**This skill does NOT work on:**

| 场景 | 为什么 |
|------|--------|
| 单篇笔记深化 | 用 note-deepen skill |
| 笔记整理/归档 | 本 skill 不改文件，只输出洞察 |
| 翻译/摘要 | 功能完全不同 |

## Key Concepts

**结构缺陷信号（Structural Defect Signals）** — 笔记中暴露"思考不充分"的痕迹：

| 信号类型 | 定义 | 示例 |
|----------|------|------|
| **矛盾** | 两篇或多篇笔记在同一个问题上隐含了相反的立场 | A笔记说"限制激发创意"，B笔记说"给玩家最大自由度"——两者都未意识到对方的存在 |
| **缺口** | 某个概念被频繁引用但从未被单独展开；或某个论证链条缺少关键环节 | 多篇笔记提到"心流"但从未讨论心流破裂的条件 |
| **孤立** | 笔记无入链无出链，或仅存在于一个文件夹中未与任何其他笔记产生联系 | 见闻资料/中一篇被收集但从未被思考整理/引用的文章 |
| **重复** | 不同笔记以不同措辞表达了同一个核心观点，但作者未意识到它们是同一件事 | 快速思考/中三篇笔记都在说"约束即设计"但措辞各异 |
| **一面倒** | 对某个主题只有一种视角的笔记，完全缺少对立面或替代方案 | 大量笔记赞美"玩家驱动"，零笔记讨论"设计师引导"的价值 |

**相邻可能（Adjacent Possible）** — 最佳洞察的位置。不是用户已经深知的领域（太无聊），也不是完全无关的领域（太跳跃），而是与用户已知领域刚好相邻、一步之遥但从未踏入的区域。

**洞察的质量标准** — 每个洞察必须至少满足以下之一：

1. **矛盾揭示**：你的笔记中 A 处说 X，B 处暗示 ¬X，你从未意识到
2. **隐含前提挖掘**：你的某个观点依赖一个未言明的假设，而这个假设值得质疑
3. **跨域桥接**：两个不同领域的笔记可以用同一个深层结构连接
4. **行动缺口**：你写了很多关于某个问题的思考，但从未转向"那我该怎么做？"
5. **盲区映射**：你在某个主题上有一面倒的笔记，完全缺少对立视角

**拒绝空洞洞察** — 以下不算有效洞察：
- "你应该多写笔记"（废话）
- "A 和 B 都很重要"（没有信息量）
- "这个话题值得深入思考"（没有说出深入什么）
- 任何其否定是荒谬的陈述

## Workflow

### Phase 1: 预扫描（轻量级，不深度读取）

用 Grep/Glob/Bash 工具扫描整个 vault，收集结构信号。**不要在此阶段读取笔记全文。**

**1.1 孤立笔记检测（区分链接方向）**

```bash
# 找出没有出链的笔记（不包含 [[ 的 .md 文件）
# 找出没有入链的笔记（文件名从未被其他笔记的 [[ 引用）
```

- 用 Grep 搜索 `\[\[` 的出现，构建链接关系
- 区分两种孤立信号，含义不同：
  - **只有出链无入链**：你从它出发去了别处，但再也没人回来引用它——被遗弃的中转站
  - **只有入链无出链**：别人都指向它，但它自己不指向任何地方——被当作终点但从未被展开
  - **既无出链也无入链**：完全孤立——收集了但未消化
- 优先关注 `见闻资料/` 和 `资料及书影音笔记/` 中的孤立笔记

**1.2 文件夹间断裂检测**

- 统计每个文件夹的出链目标分布：文件夹 A 的笔记链接到了哪些其他文件夹？
- 找出**零互链的文件夹对**：两个文件夹之间没有任何 wikilink 连接
- 这类信号能发现笔记级别检测不到的跨域孤立（如"炒股票"文件夹与"游戏设计"文件夹完全断裂）
- 优先级：两个文件夹都有 5 篇以上笔记的零互链对更有价值（小文件夹的零互链可能只是因为内容少）

**1.3 短笔记检测**

- 找出 `快速思考/` 中字数少于 50 字的笔记——这些可能是被遗弃的半成品想法
- 找出 `思考整理/` 中字数少于 100 字的笔记——这些可能是未完成的思考

**1.4 概念频率 vs. 展开深度**

- 用 Grep 统计高频概念词（如反复出现的游戏设计术语、商业概念）
- 交叉检查：这些高频概念是否有对应的专门笔记展开？如果没有 → 缺口信号

**1.5 潜在重复检测**

- 用 Grep 搜索不同笔记中相似的关键短语
- 重点关注 `快速思考/` 内部的重复——短笔记容易重复表达同一想法

**1.6 时间维度信号**

- 找出创建后**从未修改**的笔记（frontmatter 中 `created` 与 `modified` 相同，或无 `modified` 字段）
- 找出**超过 6 个月未修改**的笔记——可能已被遗忘
- 时间信号与其他信号交叉时价值最高：一篇"长期未修改 + 孤立"的笔记比一篇"长期未修改但有入链"的笔记更可能是被遗忘的

**1.7 读取历史索引**

- 读取 `日常洞察/洞察索引.md`（如果存在），从索引表中获取已推送过的洞察和被拒绝的主题，避免重复
- **只读索引文件，不读详情文件**——索引始终轻量（几百字），不会随积累膨胀

**1.8 安静日判断**

如果 Phase 1 扫描结果中：
- 无强信号（无零互链文件夹对、无高频孤立笔记、无潜在矛盾）
- 且最近一次运行在 3 天以内

→ 输出"本次扫描未发现强结构信号，建议有新笔记后再运行"，跳过后续 Phase。不要把弱信号硬凑成洞察。

### Phase 2: 候选选择（从信号中选最有价值的 5-8 篇笔记）

根据 Phase 1 的信号，选择 5-8 篇最有洞察潜力的笔记。优先级：

| 优先级 | 信号组合 | 为什么 |
|--------|----------|--------|
| 🔴 最高 | 零互链文件夹对中的笔记 | 跨域孤立是最有价值的信号——两个知识领域完全断裂，但可能有深层联系 |
| 🔴 最高 | 孤立 + 高频概念相关 | 一个重要概念被反复提及但某篇关键笔记从未被关联 |
| 🟠 高 | 只有入链无出链的笔记 | 被当作终点引用但从未被展开——高频引用的"黑箱" |
| 🟠 高 | 短笔记 + 与其他笔记有主题重叠 | 可能是被遗弃的半成品，与已有思考有隐含联系 |
| 🟡 中 | 潜在矛盾 | 两篇笔记隐含对立，但未正面交锋 |
| 🟡 中 | 长期未修改 + 孤立 | 时间强化了孤立信号——被遗忘的概率更高 |
| 🟢 低 | 单纯孤立 | 可能只是不重要的笔记 |

**选择原则：**
- 至少跨 2 个不同文件夹选笔记（增加跨域桥接的可能性）
- 至少选 1 篇来自 `见闻资料/` 或 `资料及书影音笔记/` 的笔记（资料型笔记最容易被遗忘）
- 至少选 1 篇来自 `快速思考/` 的笔记（碎片想法最可能有未展开的洞察）

### Phase 3: 深度阅读 + 洞察生成

**3.1 深度阅读**

- 读取 Phase 2 选出的 5-8 篇笔记全文
- 对每篇笔记，跟随其 wikilinks 读取直接关联的笔记（最多 1 层深度）
- 目标：理解每篇笔记的核心主张和它所在的知识网络

**3.2 结构分析**

在阅读过程中，标记：
- 笔记间的隐含关联（主题相近但未互链）
- 论证链条的缺失环节
- 隐含但未言明的前提假设
- 重复表达的核心观点
- 一面倒的视角

**3.3 生成 3 个洞察**

从分析结果中提炼 3 个最有价值的洞察。每个洞察必须：

- 基于**具体的笔记证据**（不能凭空编造）
- 通过**相邻可能**测试（与用户已知领域相邻但未踏入）
- 通过**非空洞**测试（其否定是一个可辩护的立场）
- 如果可能，包含**外部视角**（见 3.4）

**3.3.1 推理强度分级**

每个洞察必须标注推理强度，区分确凿发现和推测性关联：

| 级别 | 标签 | 定义 | 示例 |
|------|------|------|------|
| **强** | 🔴 | 证据直接支持推理，且排除了合理的替代解释 | 笔记 A 说 X，笔记 B 说 ¬X，且两者讨论的是同一个具体问题 |
| **中** | 🟡 | 证据支持推理，但存在合理的替代解释 | 笔记 A 和 B 都提到"约束"，且在相似语境下，但可能只是巧合 |
| **弱** | 🟢 | 证据与推理相关，但推理链有跳跃或模糊地带 | 笔记 A 的领域和笔记 B 的领域有"某种相似"，但具体连接点不明确 |

**分级标准**：
- 证据是否**直接**支持结论，还是需要额外的隐性假设？
- 该推理是否有**合理的替代解释**？（如有 → 降级）
- 如果删除任何一个证据，推理是否仍然成立？（不成立 → 证据直接支持 → 强；仍成立 → 证据冗余 → 检查是否有更强的表述）

**输出时标注**：每个洞察的信号类型后追加推理强度，如 `**信号类型**：矛盾 / 🔴强`。弱推理洞察不超过 1 个。

**3.4 外部视角扩展（可选但推荐）**

对最有潜力的 1-2 个洞察，用 WebSearch 搜索：
- 该洞察在学术/行业中的正式名称或相关理论
- 与该洞察对立的观点或反例
- 实际应用案例

将搜索结果融入洞察的呈现中，标注来源。

### Phase 3.5: 交叉验证（防幻觉）

**核心原则：洞察的价值在于可信。一个有趣但不可信的洞察比没有洞察更糟——它会造成污染。**

此阶段紧接 Phase 3，在输出前必须完成。分两个维度验证：

#### 维度 A：内源验证（vault 内引用）

**A.1 引文核查**

对每个洞察中出现的 `[[笔记名]] 说："[具体引用]"` 格式：

- 用 Grep 在该笔记原文中搜索引用的关键词/短语
- 确认引用确实出现在原文中，且语境未被扭曲
- 如果引用无法在原文中找到 → **删除该引用，或降级为"可能相关"而非"说"**

**A.2 链接存在性**

对每个洞察中出现的 `[[wikilink]]`：

- 用 Glob 确认该文件在 vault 中确实存在
- 如果文件不存在 → **删除该链接**，换用实际存在的笔记

**A.3 全称判断核查**

对洞察中出现的全称判断——"从未""零笔记""没有任何""完全缺少"等：

- 用 Grep 在相关文件夹中搜索反例
- 如果找到反例 → **将全称判断改为"很少""几乎没有"等有限判断**
- 如果无法确认 → **标注为"[未验证]"**

#### 维度 B：外源验证（网络引用）

**B.1 事实核查**

对每个外部引用（人名、理论名、书名、年份、概念定义）：

- 用 WebSearch 交叉验证：搜索 `"[人名] [概念]"` 或 `"[书名] [作者]"`
- 确认以下信息准确：
  - 人名是否真实存在，是否确实与该领域相关
  - 书名/论文名是否真实，作者是否正确
  - 年份是否准确
  - 概念的核心定义是否与来源一致
- 如果无法验证 → **标注为"[待验证]"**，绝不假装确认

**B.2 归因核查**

对"某人说某观点"的归因：

- 搜索该引言/观点的原始出处
- 确认确实出自该人之口/笔，而非二手转述的误传
- 特别注意：名人名言是最常见的幻觉来源——如果没有找到原始出处 → **删除归因，改为"有一种观点认为"**

**B.3 对立视角核查**

对外部视角中"对立观点"的声明：

- 搜索是否真的存在与该洞察对立的观点/理论
- 如果搜索结果中找不到实质性对立面 → **删除"对立观点"声明**，不要编造不存在的争议

**验证结果处理**

| 问题类型 | 处理方式 |
|----------|----------|
| 引文不准 | 修正措辞或删除该引用 |
| 链接不存在 | 删除，换用实际存在的笔记 |
| 全称判断有反例 | 降级为有限判断 |
| 外部事实无法验证 | 标注 [待验证]，或删除 |
| 归因无法确认 | 删除具体人名，改为泛指 |
| 对立观点不存在 | 删除对立观点声明 |
| 洞察核心逻辑依赖幻觉证据 | 重新生成该洞察或替换 |

### Phase 4: 输出

以固定格式输出 3 个洞察：

```markdown
## 🔍 Insight Dig 结果

### 洞察 1：[一句话标题]

**信号类型**：矛盾 / 缺口 / 孤立 / 重复 / 一面倒 | 推理强度：🔴强 / 🟡中 / 🟢弱

**你笔记中的证据**：
- [[笔记A]] 说："[具体引用]"
- [[笔记B]] 暗示："[具体引用]"
- 但两者从未被关联

**洞察**：[2-4 句话的非显而易见的发现。必须说出"所以呢"——这个发现意味着什么？]

**如果你要深入**：[一个具体的行动建议，比如"可以写一篇笔记对比 X 和 Y"，或"在 [[笔记A]] 中补充 Z 视角"]

**外部视角**（如有）：[相关理论/案例/对立观点，附来源。未通过外源验证的标注 [待验证]]

---

### 洞察 2：[同上格式]

---

### 洞察 3：[同上格式]

---

💡 对某个洞察不感兴趣？说 **"换 1"** / **"换 2"** / **"换 3"** 来替换特定洞察，或说 **"全换"** 重新来一轮。
```

### Phase 5: 记录（两层文件结构，索引始终轻量）

**关键原则：洞察不能只存在于对话中，必须持久化到笔记文件，否则对话一关就找不到。**

采用**两层文件结构**，避免单文件随积累膨胀：

| 层 | 文件 | 内容 | 读取时机 |
|----|------|------|----------|
| **索引层** | `日常洞察/洞察索引.md` | 每次运行一行：日期 + 3 个洞察标题 + ✅/❌ | 每次 Phase 1 必读，用于防重复 |
| **详情层** | `日常洞察/洞察-YYYY-MM-DD-N.md` | 该次运行的 3 个完整洞察 | 想回顾时才读，Skill 运行时不读 |

**5.1 创建详情文件**

每次运行创建一个新文件 `日常洞察/洞察-YYYY-MM-DD-N.md`，N 为当日第几次运行。文件内容：

```markdown
---
created: YYYY-MM-DD
description: Insight Dig 第 N 次运行结果
---

# 洞察 YYYY-MM-DD #N

## 洞察 1：[完整标题]

**信号类型**：[类型]

**你笔记中的证据**：
- [[笔记A]] 说："[引用]"
- ...

**洞察**：[完整内容]

**如果你要深入**：[完整内容]

**外部视角**（如有）：[完整内容]

---

## 洞察 2：[同上完整格式]

---

## 洞察 3：[同上完整格式]
```

**5.2 更新索引文件**

在 `日常洞察/洞察索引.md` 的索引表中追加一行：

```markdown
| YYYY-MM-DD #N | [洞察1标题](洞察-YYYY-MM-DD-N.md#锚点) ✅ | [洞察2标题](洞察-YYYY-MM-DD-N.md#锚点) ✅ | [洞察3标题](洞察-YYYY-MM-DD-N.md#锚点) ✅ |
```

如果索引文件不存在，创建它并添加 frontmatter 和表头：

```yaml
---
created: [today]
description: Insight Dig 运行索引，避免重复推送同类洞察。详情见各次运行笔记。
---
```

**5.3 "换一个"后更新**

替换时：
- 在索引表中将对应洞察标记为 ❌
- 追加新洞察标题和链接，标记为 ✅
- 在对应详情文件末尾追加替换后的完整洞察内容

**为什么这样设计**：索引文件始终只包含简短的标题行，不会随积累膨胀——即使运行 100 次也只有 ~100 行表格。Phase 1 读取索引时消耗极少 token。详情文件各自独立，想回顾时在 Obsidian 中点击链接即可。

### Phase 6: "换一个"处理

当用户说"换 N"时：

1. 读取 `日常洞察/洞察索引.md`，标记被拒绝的洞察
2. 分析被拒绝洞察的特征（什么主题、什么信号类型），避免生成同类型替换
3. 回到 Phase 1 的预扫描结果，选择未被使用的候选笔记
4. 如果候选不够，重新执行 Phase 1 的部分扫描
5. 生成 1 个替换洞察
6. **对新洞察执行 Phase 3.5 交叉验证**（替换洞察不跳过验证）
7. 标注推理强度（同 Phase 3.3.1）
8. 输出替换洞察，格式同 Phase 4
9. 更新 `日常洞察/洞察索引.md`（❌ 旧洞察 + ✅ 新洞察）和对应详情文件

当用户说"全换"时：

1. 标记所有 3 个洞察为已拒绝
2. 回到 Phase 1，重新扫描（但跳过已用过的候选笔记）
3. 生成 3 个全新洞察
4. **对全部新洞察执行 Phase 3.5 交叉验证**

## Calibration

**洞察的密度比数量重要。** 3 个高质量的洞察远胜过 5 个平庸的。宁可少输出也不要输出空洞洞察。

**具体胜过抽象。** "你在 [[某笔记]] 中提到的 X 概念，和 [[另一笔记]] 中的 Y 其实是同一件事" 远好于 "你的笔记中有一些重复的概念"。

**尊重用户的领域判断。** 如果用户连续换了 2 次以上，说明选择方向可能有偏差——主动询问："你更想看到哪个方向的洞察？比如游戏设计、商业决策、还是知识管理本身？"

**不要过度解读。** 如果某篇笔记只是简短，不一定意味着"被遗忘"——可能只是作者认为它已经足够清晰。洞察必须基于证据，不是基于假设。

**外部搜索要克制。** 不是每个洞察都需要外部视角。只有在用户的知识库中确实缺少某个关键环节时，才搜索补充。搜索是为了"补一块拼图"，不是"换一张画"。

## Language

所有输出使用中文，与 vault 的主要语言一致。笔记引用使用 wikilink 格式 `[[笔记名]]`。
