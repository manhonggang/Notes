# 增量游戏——线性、多项式、指数（以及更多）增长方式详解

https://www.reddit.com/r/incremental_games/comments/2ztcfk/linear_polynomial_exponential_and_more_growth/

本教程的灵感和资料主要来自 [这个维基](https://oeis.org/wiki/Growth_of_sequences)。

如果你经常逛这个板块，应该会看到"线性""多项式"和"指数"这些术语时不时被提起。也有一些[博客和教程](http://mrhen.com/blog/?cat=11)对它们在放置类游戏平衡中的作用做了很好的阐释（有时涉及的数学还相当多）。不过，仍然有人对各种函数的增长含义感到困惑。

增长指的是**一个数列增大的速度**。在增量游戏中，这些数列通常是随时间积累的资源，或随等级递增的价格。另一个重要概念是"界限"。**我们说 B 界限 A（上界）**，意思是 B 比 A 增长得更快——即在某个时刻之后，B 永远大于 A（下界的定义类似）。

注意，界限关注的是数列变大的速度，而非具体数值。来看一个例子：

A：1,000,000，2,000,000，3,000,000……

B：1, 4, 9, 16……

我们可能觉得 A 增长更快，因为它的数值大得多。然而，经过一段（很长的）时间后，情况会变成这样：

A：9.99999E11, 1.0E12, 1.000001E12

B：9.99998E11, 1.0E12, 1.000002E12

因此，B 的增长比 A 更快。

当一个数列同时被同一个函数从上下两个方向界限时，**我们就说它的增长方式与该函数相同**，例如"二次增长"。同样，我们关注的是数列的演变方式，而非具体数值。这个概念之所以有用，是因为我们可以借此对数列进行分类，将其与已知的数学函数做比较。

███

**三位一体。**

线性、多项式（次数 ≥ 2）和指数是增量游戏中最常用的三种增长率。原因在于它们依次相互界限（线性 < 多项式 < 指数），并且**可以组合使用，在产量与价格之间平衡游戏进度**。

如果价格增长慢于产量，迟早有一天买东西会变得毫无压力——因为产出远超花费，平衡就此打破。如果两者增长速率相同，购买某物所需的时间几乎恒定（例如每 10 分钟买一次），这可能有趣，也可能乏味。如果价格增长更快，购买新东西所需的时间会越来越长，进度随之放缓。设计师正是利用这种放缓来让玩家撞上"墙"——进度过于缓慢，迫使玩家采取某种行动（声望重置、进入游戏新区域等）才能继续推进。

接下来我们将逐一介绍每种增长方式。

█

**线性。**

**描述：** 以线性函数的方式增长。

**示例函数：** x

**示例数列：** 1, 2, 3, 4, 5……

[图像](http://bit.ly/1CImVpC)

**解释：** 虽然我们通常把线性和多项式当作不同的东西来讨论，但线性其实是一种多项式，确切地说是次数为 1 的多项式。

线性增长是大多数人最熟悉的增长方式，因为它在日常生活中无处不在。这个数列以固定速率增长，相邻两项之间的差值恒定。它也符合人们对事物发展的直觉：如果去一个地方需要 1 小时，去两倍远的地方大约需要 2 小时；如果一件东西卖 100 美元，买 5 件就要 500 美元，以此类推。

**可能用途：** 线性增长几乎总是被用作资源产出率。它简单、易操作，人们也熟悉它——他们天生就会处理线性关系，也能轻松预估其走势。

**超线性。**

**二次。**

**描述：** 以次数为 2 的多项式方式增长。

**示例函数：** x²

**示例数列：** 1, 4, 9, 16, 25……

[图像](http://bit.ly/1bkSsBR)

**解释：** 当我们说"多项式"时，通常指次数 ≥ 2 的多项式。次数恰好为 2 的多项式有一个特殊名称——二次多项式。

从示例数列可以看出，与线性增长不同，这里相邻两项之间的间距越来越大。我们来看看相邻两项之间的差值：

3, 5, 7, 9, 11……

可以看到，虽然差值在增大，但增大的速率恒定为 2。

人们理解二次增长的难度更大，因为它不如线性增长那样在日常生活中常见。少数例子之一是：在体育锦标赛中，每支队伍都要和其他每支队伍比赛一场。此时，总比赛场数的量级为 x²（灵感来自[这篇帖子](http://www.quora.com/What-are-some-examples-of-quadratic-growth-that-would-be-applicable-to-high-school-students)）。

**可能用途：** 由于二次增长介于线性和指数之间，它既可以用于定价，也可以用于资源产出。一个典型的资源产出例子是"能生产建筑的建筑"，如 [Derivative Clicker](http://gzgreg.github.io/DerivativeClicker/) 中的设计。

**三次、四次等。**

**描述：** 次数为 3（x³）、4（x⁴）等的多项式。与二次的描述相同，只是每一级增长更快。

█

**指数。**

**描述：** 数列的增长率是当前值的一个倍数。

**示例函数：** 2ˣ

**示例数列：** 2, 4, 8, 16, 32, 64, 128, 256……

[图像](http://bit.ly/1EzAhQ4)

**解释：** 指数增长是人们理解起来最困难的一种。我们知道它增长很快，但往往不完全理解"快"意味着什么。它常被误认为某个高次多项式，因为高次多项式也能产生很大的数值。

与多项式类似，我们可以看到相邻数字之间的间距在增大。来看看相邻两项之间的差值：

2, 4, 8, 16, 32, 64, 128

可以看到，与多项式不同的是，相邻两项之间差值的变化量并不恒定——它在不断增大。这意味着数字之间的间距不仅随时间拉大，而且这种拉大的趋势还在加速。

指数增长在现实中也存在，但通常足够复杂以至于让人困惑。例如，贷款利率或银行储蓄的利息遵循指数增长，因为每年都会乘以一个比率。某些生物的种群数量也呈指数增长，比如病毒的总量每天翻一倍。

**可能用途：** 指数增长几乎专门用于定价，因为它同时界限了线性和多项式，能确保玩家的进度随时间逐渐放缓。

**增长动物园。**

除了上述三种增长函数，**还有许多更慢或更快的函数**。其中大多数鲜为人知，有些对增量游戏用处不大，但另一些在实现有趣的玩法机制方面潜力巨大。

以下各节将从慢到快依次介绍不同的增长速度。

█

**亚多项式。**

█

**迭代对数。**

**描述：** 以[迭代对数](http://en.wikipedia.org/wiki/Iterated_logarithm)（log*）方式增长。

**示例函数：** log* x

**示例数列：** log* 2 = 1, log* 4 = 2, log* 16 = 3, log* 65536 = 4, log* 2⁶⁵⁵³⁶ = 5

**解释：** 迭代对数函数的含义是"需要对一个数取多少次对数才能使其 ≤ 1？"它增长得非常、非常慢。有多慢？看看数列就知道了——当自变量为 2⁶⁵⁵³⁶ 时，函数值才 5。在实际应用中，我们可以认为这个函数的值 ≤ 6。

**可能用途：** 我能想到的唯一用途，就是用于我们希望几乎保持不变的值。

█

**对数。**

**描述：** 以对数方式增长。

**示例函数：** log x

**示例数列：** 1, 1, 1, 2, 2, 2, 2, 2, 2, 2, 2, 3, 3……

[图像](http://bit.ly/1EDkqT6)

**解释：** 指数的逆运算，这个函数随时间推移增长得越来越慢。到某个时刻，它几乎不再增长。

**可能用途：** 这个函数可以用来实现生成器或升级的边际递减效果——你买得越多，每多买一个带来的收益就越少。

**多项式。**

█

**亚线性。**

**描述：** 以多项式速率增长，但比线性更慢。

**示例函数：** √x

**示例数列：** 1, 1, 1, 2, 2, 2, 2, 2, 3, 3, 3, 3……

[图像](http://bit.ly/1MYp7Jb)

**解释：** x 的平方根即 x^(1/2)。如果我们把线性看作 x¹，那么平方根比线性增长更慢就顺理成章了。而且，虽然它比线性慢，但不像对数那么"冷酷"——仍然在缓慢前进。这种增长也可以推广到立方根、四次方根等，每一级都比上一级更慢。

**可能用途：** 一些游戏通过对资源产出施加惩罚来减缓玩家进度。√x 曲线可以用于这种惩罚。由于线性界限 √x，我们可以减缓产出而不至于完全停止。

█

**超线性但亚二次。**

**描述：** 增长比线性快，但比二次慢。

**示例函数：** x · log x

**示例数列：** 200, 202.43, 204.87, 207.32, 209.77, 212.22, 214.68, 217.14, 219.60, 222.07

[图像](http://bit.ly/1bkSxFK)

**解释：** 它比线性增长略快，又比二次增长慢得多。可以推广到更高次多项式，例如 x² · log x。

**可能用途：** 可以用来略微提升产出，例如根据当前资源数量提供产出加成。

█

**超多项式但亚指数。**

**描述：** 增长比任何多项式都快，但比任何指数都慢。

**示例函数：** x^(log x)

**示例数列：** 1, 3, 6, 13, 24, 44, 75, 124, 200……

[图像](http://bit.ly/1CHqomR)

**解释：** 它的行为更接近指数而非多项式，但仍被指数所界限。

**可能用途：** 这是一个非常有趣的函数。人们通常用指数增长来定价以减缓进度。而使用这个函数，我们同样能在长期实现减速效果，但过程会更长，从而拉长玩家的进度曲线。

**超指数但亚迭代指数。**

█

**指数多项式。**

**描述：** 指数的指数部分为多项式的指数函数。

**示例函数：** 2^(x²)

**示例数列：** 2, 16, 512, 65536, 33554432, 68719476736, 5.6295E+14, 1.84467E+19

[图像](http://bit.ly/1BFKU1J)

**解释：** 比普通指数更快的指数变体。

**可能用途：** 如果资源呈指数增长，这个函数可以用于定价以界限产出。也可以在普通指数增长不够用时使用。

█

**双重指数。**

**描述：** 指数的指数部分仍为指数的函数。

**示例函数：** 2^(2ˣ)

**示例数列：** 4, 16, 256, 65536, 4294967296, 1.84467E+19, 3.40282E+38, 1.15792E+77

[图像](http://bit.ly/1EDkx12)

**解释：** 这是一个指数本身也在指数增长的数列。它也很难展示——在图像中我们几乎看不清，但红线确实比绿线增长更快。你看到底部那条细小的蓝线了吗？那是一条普通指数。

**可能用途：** 这个数列增长得如此之快，几乎已经到了即使使用大数库也能处理的极限。

█

**超双重指数但亚迭代指数。**

**描述：** 定义固定高度的[幂塔](http://mathworld.wolfram.com/PowerTower.html)。

**示例函数：** x^(x^x), 2^(2^(2ˣ))

**解释：** 我们把嵌套的幂运算称为幂塔。幂塔的高度就是幂运算的层数，例如 x^(x^(x^x)) 就是一个高度为 4 的幂塔。

**迭代指数。**

█

**超幂（Tetrational）。**

**描述：** 以[超幂](http://en.wikipedia.org/wiki/Tetration)函数的量级增长。

**示例函数：** 2↑↑x，使用[克努特上箭头记号](http://en.wikipedia.org/wiki/Knuth%27s_up-arrow_notation)。

**示例数列：** 1, 2, 4, 16, 65536, 2⁶⁵⁵³⁶, 2^(约 19000 位数字的数)

**解释：** 你有没有想过，指数运算之后是什么？答案是超幂运算（tetration）。超幂运算定义了一个数自乘幂的次数。在这里，x 定义了幂塔的高度。它增长得极快。

有多快？看数列——仅仅 6 步，就已经到了 2⁶⁵⁵³⁶。而下一步就是 2 的一个约 19000 位数字的幂。你能想象吗？[这里](http://pastebin.com/Wp1BCe6P)是一个 19000 位数的样子——而这还只是 2 的指数。

**可能用途：** 这个函数增长得如此荒谬之快，目前没有任何大数库能容纳它。

█

**超超幂，其他超运算。**

**描述：** 超幂之后是什么？五则运算（Pentation）。再之后呢？六则运算（Hexation）。我们可以为超幂之后的每一种超运算定义增长速度。

█

**非原始递归、非递归、不可计算。**

**描述：** 最后一站。终点到了。我们已经见识了增长得荒谬至极的函数。还有什么能超越它们？答案是——我们甚至无法计算的函数。我不是说我们不知道怎么算，而是数学上已经证明这不可能。其中最著名的就是[忙海狸函数](http://en.wikipedia.org/wiki/Busy_beaver)（Busy Beaver）。

**示例函数：** Busy Beaver。

**示例数列：** 4, 6, 13, ???

**解释：** 由于这个函数不可计算，我们只知道前几个值的精确结果。然而，已经证明它比任何可计算函数都增长得更快——包括超幂、五则运算等一切。

**可能用途：** 好了，拿去做噩梦吧。
